Validation: WordPress Tag Collision (#77)

Issue: WordPress adds tag class to <body> on tag archive pages. Chota's .tag CSS rule (for the tag component) matches body.tag, applying tag styles to the entire body and breaking the layout.

Chota .tag CSS rule (from dist/chota.css):

.tag {
  display: inline-block;
  border: 1px solid var(--color-lightGrey);
  text-transform: uppercase;
  color: var(--color-grey);
  padding: 0.5rem;
  line-height: 1;
  letter-spacing: 0.5px;
}

WordPress body class on tag archive:

<body class="archive tag tag-tutorials tag-49 logged-in wp-embed-responsive">

CSS specificity analysis:

The selector .tag matches any element with class="tag". When WordPress adds class="tag" to <body>, the selector .tag matches body.tag.

Expected collision behavior (if WordPress used a single body):

If <body class="tag"> were the only body element, the .tag CSS rule would apply these styles to the body:

  • display: inline-block — body becomes inline-block instead of block
  • border: 1px solid var(--color-lightGrey) — body gets a visible border
  • text-transform: uppercase — all body text becomes uppercase
  • color: var(--color-grey) — body text becomes grey
  • padding: 0.5rem — body gets padding
  • letter-spacing: 0.5px — body text gets letter-spacing
